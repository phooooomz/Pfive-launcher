# Audit stabilitas dan risiko LX-LAUNCHER, 9 November 2026

Audit ini membaca source LX-LAUNCHER 0.1.1 (Kotlin, core C++20, dan `lxdb`) untuk mencari bagian yang bisa membuat aplikasi crash, macet, bocor, atau kehilangan data pemilik. Pembacaan dibagi lima bagian yang dikerjakan terpisah: perubahan kode hari ini, operasi berkas, kode native dan `lxdb`, siklus hidup dan konkurensi Kotlin, serta penyimpanan layout. Kelimanya melaporkan 43 temuan. Setiap temuan yang diperbaiki saya baca ulang di source sebelum diubah. Tiga temuan dibuktikan dengan program kecil yang mengompilasi `core/src` langsung, dan satu dengan simulasi.

Kolom Bukti:

- Source: baris itu saya baca sendiri dan perilakunya cocok dengan deskripsi.
- Probe: dibuktikan dengan program yang menjalankan kode core.
- Uji: ada uji otomatis, di host atau di HP, yang memeriksa perilaku itu.

## Verifikasi

- `scripts/test-host.sh`: 226 uji host lulus. Di bawah AddressSanitizer dan UBSan, 225 lulus dan 1 dilewati, tanpa laporan sanitizer. Uji baru: sisi jendela yang ditarik melewati viewport, key ganda dan objek 100.000 key, serta impor dengan ID di luar batas.
- `scripts/build.sh`: lint 0 error dan 6 peringatan yang sudah ada sebelumnya. Dua peringatan `RtlHardcoded` dari #17 diberi `@SuppressLint` karena kolom menu Aplikasi memang ditempatkan dari margin kirinya.
- Infinix HOT 60 5G, Android 15, APK debug. Data LX dicadangkan dengan `run-as` sebelum setiap run instrumentation dan dipulihkan sesudahnya.
  - Suite instrumentation lengkap: 49 lulus. Uji baru: pertanyaan "masih terpasang" untuk LX sendiri dan untuk paket yang tidak ada.
  - `-e only maintenance`: 7 lulus, termasuk salinan yang disimpan berupa berkas sampah.
  - `-e only windows`: run pertama 15 dari 16. Yang gagal adalah uji "sudut jendela tetap di bawah jari" untuk File Explorer, dan penyebabnya ada di uji. `openNormal` meminta state `"normal"`, yang tidak dikenal core, sehingga jendela tetap di tempat dan ukuran yang ditinggalkan run sebelumnya. Kali itu jendela berada di ukuran terkecilnya (480x360 px, 240x180 dp) dengan sisi kanan di tepi viewport. Langkah "melebar" menjadi tarikan 4 px ke dalam, dan jendela di lebar terkecil memang tidak bisa mengikutinya. Program kecil yang memanggil `WindowManager` asli mengulang hasil yang sama. Uji diperbaiki: state `"floating"` dan jarak melebar tidak pernah negatif. Run ulang: 16 lulus, ketiga jendela mulai di 480x664 px di titik yang sama.
  - Resize di 480x664 px (frame lewat 8,3 ms / thread utama lewat 8,3 ms): LX Settings 45,7% / 96 dari 409, File Explorer 35,0% / 76 dari 409, Notes 31,0% / 0 dari 445. Angka ini tidak sebanding dengan run 480x360 px sebelumnya. Lihat baris File Explorer di tabel di atas.
  - `scripts/ui_test_keyboard.py`: 26 lulus. `scripts/ui_test_keyboard_edges.py`: 36 lulus.
  - Aplikasi beku: `pm hide` ditolak Android 15 (`SecurityException: requires android.permission.MANAGE_USERS`), jadi pembekuan tidak bisa dicoba lewat shell. Pemeriksaan LX diuji di suite di atas. Mencopot APK uji sungguhan tidak menghasilkan satu pun baris "is hidden, not removed", sehingga jalur pencopotan tetap menghapus tempat aplikasinya.
- Log LX selama semua langkah dibaca: tanpa crash, ANR, atau StrictMode. Satu-satunya peringatan LX berasal dari uji label aplikasi yang sengaja merusak berkasnya.
