# Threat model

Cakupan: aplikasi LX-LAUNCHER versi 0.1.1, tanpa server. Izin internet dipakai LX Bridge untuk alamat loopback, dan oleh Tedit untuk Open VSX, image Debian x86_64 dari GitHub, dan program yang pengguna jalankan di Debian. Diperbarui 2 November 2026 untuk File Manager, mesin arsip, jendela aplikasi, LX Bridge, dan `lxdb`, 3 November 2026 untuk tombol tutup dan catatan LX Bridge, 10 November 2026 untuk akses berkas lewat shell, dan 12 November 2026 untuk Debian dan ekstensi di Tedit.

## Aset

- Tata letak pengguna dan catatan (`files/layout.lxl`, `files/notes.lxl`).
- Akses folder yang diberikan lewat Storage Access Framework.
- Peran Home: aplikasi yang memegangnya selalu berjalan dan menerima tombol Home.
- Berkas pengguna di penyimpanan bersama, kalau Akses semua file diberikan.
- Hak shell (uid 2000) yang didapat LX lewat LX Bridge, sampai ponsel dimulai ulang.
- Debian milik Tedit (`no_backup/linux/debian`) dan ekstensi VS Code yang terpasang (`files/tedit/extensions`).

## Permukaan serangan dan mitigasi

| Ancaman | Jalur | Mitigasi | Bukti |
|---|---|---|---|
| Berkas tata letak berbahaya | Impor dari berkas pilihan pengguna | Batas 1 MB sebelum parsing. Parser JSON berbatas kedalaman 32, string 64 KB, 200.000 elemen. Validasi skema per entitas. Widget Android dibuang saat impor | `Json.*`, `Fuzz.ImportSurvivesMutatedLayouts` (3.000 mutasi), instrumentation "import rejects hostile and oversized documents" |
| Path traversal | Nama berkas atau ID di tata letak | Kunci aplikasi divalidasi (`validate::isAppKey`): tanpa `/` di nama paket, tanpa `..`. Wallpaper hanya `system`, `builtin:`, `color:#RRGGBB`, `content://`, atau `local:<token>` dengan token `[a-z0-9_.-]` sampai 48 karakter yang dibuka di folder privat `wallpapers/`. Gambar yang diimpor dibatasi 40 MB dan harus bisa didecode sebelum disimpan. Nama berkas di LX Files menolak `/`, `\`, `.`, `..`, dan karakter kontrol | `DesktopTest.FromJsonKeepsValidEntriesWhenSomeAreBroken`, `DesktopTest.JsonRoundTrip` (`local:../../etc/passwd` ditolak) |
| Berkas tersimpan rusak | Crash saat menulis, kerusakan penyimpanan | Penulisan atomik dengan `fsync`, checksum CRC32, cadangan `.bak`, karantina `.corrupt` | `Store.*`, `Fuzz.EnvelopeRejectsMutations` |
| Intent palsu | Aplikasi lain mengirim intent ke Activity | Activity hanya menerima MAIN/HOME dan MAIN/LAUNCHER. Tidak ada extra yang dibaca dari intent luar. Tidak ada receiver yang diekspor. Satu-satunya service yang diekspor hanya bisa diikat sistem, dan satu-satunya provider yang diekspor hanya menerima shell (lihat di bawah) | `AndroidManifest.xml` |
| Batas JNI | Teks dari Java, bitmap | Konversi UTF-16 ke UTF-8 manual (JNI modified UTF-8 tidak dipakai). Handle null dicek. Format bitmap selain RGBA_8888 ditolak. Satu mutex per engine | Instrumentation "strings outside the BMP survive the JNI boundary", "wallpaper and blur render into an Android bitmap" |
| Memory corruption di C++ | Parser, blur, geometri | RAII untuk file descriptor, tanpa `new` mentah di luar handle JNI, nilai NaN dan tak hingga ditolak di setiap API geometri | 91 test lulus di bawah AddressSanitizer dan UBSan |
| Kebocoran data | Log, cadangan cloud | `allowBackup=false` dan data extraction rules mengecualikan semua domain. Log hanya berisi status, tidak berisi isi catatan atau nama berkas. Catatan LX Bridge di `no_backup/lx-bridge.log` berisi waktu, status, port loopback, dan pesan galat, paling banyak 300 baris, di folder privat LX | `AndroidManifest.xml`, `res/xml/data_extraction_rules.xml` |
| Penyalahgunaan izin | Izin berlebihan | `REQUEST_DELETE_PACKAGES` (meneruskan ke dialog uninstall Android) dan `ACCESS_NETWORK_STATE`, ditambah izin penyimpanan File Manager yang hanya diminta setelah pengguna mengetuknya. Tanpa internet, aksesibilitas, overlay, atau notifikasi | Halaman Privasi di LX Settings membaca daftar izin dari paket yang terpasang |
| Arsip berbahaya | ZIP, TAR, atau TAR.GZ dari internet yang diekstrak pengguna | Setiap path diperiksa di C++ (`lx::archive::checkPath`): `..`, path absolut, huruf drive, backslash, karakter kontrol termasuk C1 dan bidi, UTF-8 rusak, komponen di atas 255 byte, path di atas 4096 byte. Symlink, hardlink, perangkat, dan FIFO dilewati; entri di bawah symlink dianggap keluar. Isi diekstrak ke folder staging tersembunyi dan baru dipindahkan setelah semua entri lolos | `ArchivePath.*`, `ArchiveSafety.*`, instrumentation "archive paths that escape...", `scripts/ui_test_file_manager.py` (evil.zip) |
| Bom dekompresi | Rasio kompresi ekstrem, entri ZIP yang tumpang tindih | Batas entri (100.000), batas byte total dan per entri (ruang kosong tujuan dikurangi 64 MiB, paling besar 256 GiB), rasio 1000:1 untuk seluruh arsip dan per entri ZIP, deteksi rentang tumpang tindih di central directory, ukuran keluaran tidak boleh melewati ukuran yang dinyatakan | `ArchiveLimits.*`, `ArchiveSafety.*`, `ArchiveFuzz.*` |
| Arsip rusak | Byte acak, arsip terpotong | Parser berbatas tanpa memuat arsip ke memori, CRC-32 ZIP dan CRC gzip diperiksa, header TAR dengan checksum; fuzz dengan seed tetap | `ArchiveFuzz.*` (sampai 20.000 iterasi), `ArchiveTruncation.*`, ASan/UBSan |
| Kehilangan data saat operasi berkas | Pindah antar penyimpanan, Ganti, pembatalan, proses mati | Tulis ke `.lxpart` lalu ganti nama, pertukaran lewat `.lxkeep`, sumber dihapus hanya setelah salinannya terverifikasi, pengenalan berkas yang sama lewat dua jalan (`Aliases`), journal untuk sisa setelah proses mati | `docs/architecture/file-manager.md`, uji JVM agen penyimpanan (71 pemeriksaan) |
| Berbagi berkas | Aplikasi lain membuka URI dari "Bagikan" | `ShareProvider` tidak diekspor, hanya lewat izin URI; token acak 128 bit, bukan path; hanya mode baca; `lstat` sebelum dan `fstat` sesudah membuka untuk menolak berkas yang ditukar | `files/ShareProvider.kt` |
| Hak shell | `lxdb`, daemon native sebagai uid shell (ADR-008) | Binder hanya menjawab uid LX, dari `sender_euid` yang diisi kernel. Hanya layar milik pemanggil, maksimum 16 layar, ukuran dan dpi dibatasi, pengguna LX atau profil kerjanya. Tombol sistem global (POWER, volume, panggilan, tangkapan layar) ditolak di daemon, dan tombol tanpa bentuk yang dikenal dibuang. Layar dilepas saat LX mati. `close` hanya menghapus tugas di layar milik pemanggil, dan hanya dipakai saat pengguna menutup jendelanya; hak ini tidak baru, karena `exec` sudah setara shell. Tidak ada soket jaringan | `tests/unit/lxdb_rules_test.cpp`, `scripts/ui_test_lxdb.sh`, `scripts/ui_test_display_awake.sh` |
| Perintah shell lewat `lxdb` | `IEmbedService.exec`, soket `@lxdb-u<pengguna>` | `exec` hanya untuk uid LX. Soket hanya menerima shell dan root menurut `SO_PEERCRED`, dan SELinux lebih dulu menolak proses aplikasi. Perintah `lxdb` memeriksa uid daemon sebelum mengirim deskriptor, karena nama soket abstrak siapa cepat dia dapat | `scripts/ui_test_lxdb.sh`, `LxdbRules.*` |
| Berkas lewat shell | File Manager dengan hak shell (10 November 2026) | Path selalu dikutip tunggal, jadi nama berkas tidak pernah menjadi perintah. Tautan simbolik tidak diikuti oleh salin, hapus, atau penjelajahan. Hapus memakai `rmdir` untuk folder dan `rm -f` untuk berkas, tidak pernah `rm -r` atas pilihan pengguna; folder dihapus isinya satu per satu seperti di backend lain. Cache Android/data dikosongkan hanya untuk path yang berakhir `/cache` di bawah `Android/data/`. Nama paket diperiksa dengan pola sebelum masuk perintah. Salinan untuk Bagikan ada di cache privat LX dan dihapus setelah sehari | `FileManagerChecks.kt` (`-e only fm`) |
| Tedit: terminal, tugas, dan repositori | Tedit (11 November 2026) | Terminal dan tugas menjalankan `/system/bin/sh` sebagai uid LX, tanpa root dan tanpa izin baru; perintah tugas berasal dari `.tedit/tasks.json` di folder yang dipilih pengguna sendiri, dan path berkas yang dijalankan dikutip tunggal. Tugas dihentikan setelah batas waktu dan saat jendela ditutup. Pembaca git hanya membaca; tidak ada penulisan ke `.git`. Cadangan perubahan yang belum disimpan ada di `files/tedit/backup` milik LX dan dihapus saat berkas disimpan atau dibuang. Log `LxTedit` hanya mencatat ekstensi, ukuran, jumlah baris, dan durasi, tidak pernah isi atau path berkas. Tidak ada akses jaringan | `TeditChecks.kt` (`-e only tedit`) |
| Parcel dari LX | Isi transaksi ke `lxdb` | Pembaca parcel memeriksa setiap panjang, gagal sekali untuk seluruh transaksi, dan hanya menerima binder di offset yang didaftarkan kernel, jadi byte biasa tidak bisa menjadi handle | `LxdbParcel.*` |
| Framework yang berubah | ROM yang menggeser nomor transaksi atau mengubah parameter | Nomor dibaca dari `framework.jar` ponsel, dan panggilan dengan parameter lain dimatikan. Pembaca jar dan DEX memeriksa setiap offset | `LxdbDex.*`, termasuk 3.000 jar rusak di bawah ASan dan UBSan |
| LX Bridge | Klien ADB di proses LX, `lxdb` yang hidup sampai reboot, `WRITE_SECURE_SETTINGS` | Soket hanya ke loopback. Pairing memakai kode Android lewat SPAKE2 di dalam TLS. Kunci RSA disegel dengan Android Keystore. Binder `lxdb` diterima hanya dari uid shell atau root, dengan token acak 128 bit dari prefs privat, dan `lxdb` dari APK lain ditolak. Sebaliknya `lxdb` hanya menerima jawaban dari uid LX. LX hanya menulis `adb_wifi_enabled`. Port palsu dari aplikasi lain hanya melihat kunci publik dan token, yang tidak berguna tanpa uid shell | `BridgeChecks.kt`, `EmbedChecks.kt`, ADR-007 |
| Otomatisasi LX Bridge | `BridgeSetupService` membaca dan mengetuk Pengaturan | Layanan aksesibilitas mati secara bawaan, hanya untuk `com.android.settings` dan `com.android.systemui`, memakai batas 120 detik, dan mematikan dirinya sendiri | `BridgeChecks.kt`, ADR-007 |
| Provider yang diekspor | `EmbedBinderProvider` | Dilindungi `INTERACT_ACROSS_USERS_FULL`, yang hanya dimiliki sistem dan shell, dan memeriksa uid serta token | `AndroidManifest.xml` |
| Rantai pasok | Dependensi build | Versi plugin dan library dipatok. GoogleTest diunduh dari URL rilis resmi dengan SHA-256 yang dicatat | `CMakeLists.txt`, `docs/research/dependencies.md` |
| Kunci rilis | Keystore di repository | Tidak ada konfigurasi signing. `.gitignore` mengecualikan `*.keystore` dan `*.jks` | `app/build.gradle.kts` |

## Debian dan ekstensi di Tedit

| Ancaman | Jalur | Mitigasi | Bukti |
|---|---|---|---|
| Image Debian palsu atau rusak | Unduhan x86_64, berkas yang dipilih pengguna | Hanya image dengan SHA-256 yang dicatat di kode yang diterima, diperiksa sambil dibongkar; unduhan hanya lewat HTTPS dan pengalihan ke HTTPS | `LinuxChecks`, `LinuxRuntime.SOURCES` |
| Arsip yang menulis ke luar foldernya | Nama `..`, nama absolut, symlink yang lalu dipakai sebagai folder | Nama dibersihkan dan ditolak, tidak ada yang ditulis lewat symlink, hard link dijadikan salinan | `LinuxChecks` (uji tar) |
| Penghapusan Debian mengikuti symlink ke luar | Image berisi symlink ke `/` dan path absolut | Penghapusan memakai `lstat` dan tidak pernah mengikuti symlink | `LinuxChecks` (uji hapus) |
| `.vsix` yang menulis ke luar foldernya atau memenuhi penyimpanan | Nama di arsip, ukuran | Hanya isi `extension/` yang diambil, nama yang keluar folder ditolak, batas 20.000 berkas dan 300 MB, unduhan dibatasi 200 MB dan dicocokkan dengan SHA-256 Open VSX | `ExtChecks` |
| Kode ekstensi berjalan di LX | JavaScript di `main`/`browser` | Tidak dijalankan sama sekali; yang dibaca hanya JSON, plist, dan grammar | `ExtensionStore` |
| Grammar ekstensi membekukan editor | Regex yang backtracking tanpa batas | Grammar ekstensi diwarnai di thread latar; satu baris dibatasi 20 ms di thread utama dan 500 ms di latar; pola yang tidak bisa dikompilasi dilewati; baris di atas batas panjang tidak diwarnai | `TextMateChecks`, `ExtChecks` |

## Risiko yang tersisa

- Program di Debian berjalan sebagai pengguna Android milik LX, seperti sh di terminal Tedit sebelumnya. Ia bisa membaca berkas privat LX, termasuk kunci LX Bridge, karena VHDP adalah lapisan kompatibilitas, bukan sandbox. Paket dari apt, pip, atau npm yang berbahaya mendapat akses yang sama. Halaman Linux di Tedit menyebut ini; pasang hanya paket yang dipercaya.
- Regex di grammar ekstensi dijalankan apa adanya. Batas waktu diperiksa di antara pencarian, jadi satu pencarian regex yang backtracking sangat panjang tetap berjalan sampai selesai. Sebagian besar pewarnaan grammar ekstensi berjalan di thread latar, jadi biasanya yang tertahan hanya warnanya. Baris yang sedang diketik dikerjakan di thread utama, sehingga regex seperti itu di baris tersebut masih bisa menahan editor sesaat.

- Akses semua file membuat bug di File Manager berdampak ke seluruh penyimpanan bersama. Mitigasinya adalah pola tulis-lalu-ganti-nama, konfirmasi hapus, dan pembersihan journal yang hanya menyentuh nama `.lxpart` dan `.lx-extract`.
- Selama `lxdb` berjalan, siapa pun yang bisa mengeksekusi kode di proses LX mendapat hak shell, karena `exec` menjalankan perintah apa pun sebagai uid shell. Hak shell bisa membaca log, memasang aplikasi, dan membaca penyimpanan bersama, tetapi tidak bisa membaca data privat aplikasi lain.
- Kunci adb LX memberi akses shell ke siapa pun yang berhasil menjalankan kode di proses LX dan membuka segelnya. Dampaknya setara dengan kunci adb komputer yang sudah dipasangkan. Pengguna bisa mencabutnya dari Opsi developer > Proses debug nirkabel > Perangkat yang disambungkan.
- Dengan Proses debug USB mati, LX Bridge membiarkan Proses debug nirkabel menyala selama `lxdb` berjalan. Port itu terlihat di jaringan Wi-Fi dan hanya menerima kunci yang sudah dipasangkan.
- Konten FLAG_SECURE tampil hitam di jendela Mode B, karena layar virtual dari shell tidak boleh aman.

- Hash GoogleTest dicatat saat unduhan pertama, karena project tersebut tidak menerbitkan berkas checksum. Ini trust-on-first-use.
- Widget Android menjalankan RemoteViews milik aplikasi penyedia. Isinya di luar kendali LX.
- Belum ada pemindaian kerentanan dependensi otomatis di CI. Yang ada baru daftar dependensi manual.
